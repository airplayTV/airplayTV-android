# 播放页 HUD、自动下一集与 H5 投射会话设计

## 目标

在不修改 Go API 和现有 WebSocket 控制协议的前提下，完成以下能力：

1. Android TV 播放页日志提供更明确的控制、解析、播放和错误阶段信息。
2. 播放页日志跟随视频控制层显示和隐藏，不再独立常驻。
3. 播放页连接状态跟随视频控制层显示和隐藏。
4. 播放中的扫码入口改为右上角小型二维码卡片，不遮挡主要视频内容。
5. 房间号过长时使用中间省略形式显示。
6. 多剧集视频自然播放结束后自动播放下一集，最后一集不循环。
7. H5 遥控器显示当前投射视频和剧集列表，刷新后仍可恢复并切换剧集。
8. 保留 5 秒 Presence 租约续期，但不重复输出“手机控制器已关联”。
9. 播放页日志位于左下角，最多显示 5 行并包含本地时间。

## 范围

### 修改范围

- `airplayTV-android`：播放控制层、诊断日志、播放结束事件、自动下一集和播放中二维码卡片。
- `airplayTV-vue`：投射会话快照、投射入口元数据、控制页当前视频和剧集切换界面。

### 不修改范围

- Go API、WebSocket 服务端和现有控制事件名称。
- 初始配对页的主体布局和二维码尺寸。
- 播放进度的 TV 到 H5 实时同步。
- 多控制器之间的投射会话同步。

H5 展示的是当前浏览器最近一次收到成功投射 ACK 的状态。Android 自动切换下一集后，H5 不会实时移动当前剧集高亮；这需要新增 TV 到 H5 的状态回传协议，超出本次范围。

## 总体架构

采用端内状态扩展方案：

- Android 继续通过现有视频详情接口获取剧集列表，通过 Media3 播放结束事件驱动本地自动切集。
- H5 在 `/ctl_load_Video` 获得成功 ACK 后保存版本化投射快照，控制页从快照恢复展示和切集能力。
- Presence 的 5 秒续租机制保持不变，仅在 Android 端对关联状态做边沿触发，避免续租形成重复业务日志。

该方案不增加服务端状态，保持现有房间和控制消息兼容。

## Android TV 设计

### 播放控制层可见性

`SessionUiState.infoVisible` 继续作为播放控制层的唯一可见性来源。播放页中的以下内容统一受该状态控制：

- 底部播放信息、进度和控制状态。
- 右上角 WebSocket/手机控制器连接状态。
- 左下角诊断日志。

诊断事件始终写入有界日志缓冲区，但不再使用独立超时控制播放页日志可见性。控制层隐藏时日志停止渲染；再次显示时展示最近 5 条。配对页现有的单行连接诊断行为不受影响。

### 诊断日志模型

`DiagnosticLogEntry` 增加创建时间字段，使用设备当前时区格式化为 `HH:mm:ss`。UI 每行格式为：

```text
21:36:08  CTL   收到加载视频指令
21:36:09  API   视频地址解析成功
21:36:09  PLAY  开始播放 第 03 集
```

日志阶段限定为稳定枚举式短标签：

- `WS`：连接、重连和断开。
- `CTL`：收到并接受控制命令。
- `API`：视频地址或详情解析结果。
- `PLAY`：加载、开始播放、暂停、播放结束和自动切集。
- `SKIP`：无法自动切集，例如已到最后一集或剧集列表不可用。
- `ERR`：网络解析或播放器错误的安全摘要。

详细日志不得包含完整播放 URL、URL 查询参数、Header、`mode`、原始 WebSocket JSON 或异常正文。内存缓冲仍最多保留 20 条，播放页仅显示最后 5 条，每行单行省略。

### 控制器关联日志去重

Presence 每 5 秒发送 `/ctl_pair` 等效关联事件是服务端租约机制，不能删除。Android 仅在 `controllerConnected` 从 `false` 变为 `true` 时记录“手机控制器已关联”；状态已为 `true` 时收到续租事件只刷新服务端租约，不追加日志。断开后再次关联可重新记录一次。

### 播放中二维码卡片

`/ctl_qrCode` 继续只控制播放器内的 `qrVisible`，不清空媒体、不暂停、不切换路由。显示形式改为右上角非模态卡片：

- 二维码外框约 `196dp`，二维码内容约 `172dp`。
- 卡片距顶部和右侧各保留 TV 安全区边距。
- 卡片包含“扫码连接”短标题和经过省略的房间号。
- 不再绘制全屏黑色遮罩。
- 返回键优先关闭二维码。
- 二维码显示时，右上角连接状态放置在卡片下方，避免重叠。

初始配对页仍保持现有左右分栏的大二维码布局。

### 房间号显示

新增纯函数生成中间省略文本。房间号未超出限定长度时原样显示；超出时保留前缀和后缀，例如：

```text
room-1234567890abcdef -> room-123...abcdef
```

配对页、播放中二维码卡片和其他 Android 房间号文本复用同一规则，并继续使用单行布局。

### 播放结束与自动下一集

`PlayerController` 增加只读播放事件流。`Media3PlayerController` 在当前媒体项首次进入 `Player.STATE_ENDED` 时发出一次 `PlaybackEnded`；同一媒体项的重复状态回调不得重复发出事件，加载新媒体后重置结束门控。

`SessionViewModel` 收到播放结束事件后：

1. 确认当前页面是播放器、当前媒体已提交且没有新的加载正在进行。
2. 从当前已接受的 `pid` 定位剧集索引。
3. 存在下一集时复用 `loadVideo(command.copy(pid = next.id), preserveEpisodes = true)`。
4. 已是最后一集时保持结束状态，记录一次 `SKIP`，不循环。
5. 剧集详情仍在加载时设置一次待自动切集标记；详情成功返回后再执行判断。
6. 用户在等待期间发起新的加载、上一集或下一集命令时清除旧待处理标记。
7. 下一集解析失败时保留已提交的当前剧集信息，显示现有错误层并记录安全 `ERR`，不自动连续重试。

自动切集不发送新的 WebSocket 控制消息，避免形成控制回路。

## H5 遥控器设计

### 投射会话快照

新增独立 helper 管理版本化 `localStorage` 快照。快照只在 `/ctl_load_Video` 获得成功 ACK 后写入：

```js
{
  version: 1,
  room: 'room-id',
  vid: 'video-id',
  pid: 'episode-id',
  source: 'source-id',
  title: '视频标题',
  thumb: 'https://example/thumb.jpg',
  episodeName: '第 03 集',
  episodes: [
    { id: 'episode-1', name: '第 01 集' },
    { id: 'episode-2', name: '第 02 集' }
  ],
  updatedAt: 1786630000000
}
```

约束：

- 字段在写入前统一转换、裁剪和校验。
- 剧集只保存 `id` 和 `name`，过滤无效项并限制最大数量。
- 不保存播放 URL、请求 Header、原始接口响应或 `mode`。
- 读取到无效 JSON、未知版本、缺失关键字段或房间不匹配时返回空状态，不影响遥控器基本功能。
- 继续使用应用现有的 `sourceSecret` 配置发送切集命令，不复制敏感配置到投射快照。

### 投射入口元数据

四个现有投射入口继续统一调用 `sendCastingCommand`。调用方在已有页面数据中构造候选快照：视频标题、封面、当前剧集和归一化剧集列表。`sendCastingCommand` 的执行顺序固定为：

1. 规范化 `/ctl_load_Video` 消息。
2. 等待电视 ACK。
3. 保存投射会话快照。
4. 跳转 `/control`。

发送失败、ACK 超时或服务端拒绝时不得更新快照，也不得跳转。

### 控制页布局和切集

保持现有遥控器按钮视觉风格，在控制区域下方、页脚上方新增“当前投射”卡片：

- 显示缩略图、视频标题和当前剧集名称。
- 剧集列表使用可换行的紧凑标签，当前 `pid` 高亮。
- 点击非当前剧集时发送新的 `/ctl_load_Video`。
- 切集期间禁用重复点击并显示局部加载状态。
- 只有 ACK 成功后才更新当前 `pid`、剧集名称和本地快照。
- 失败时保留旧高亮并显示“电视未连接，请重新扫码”。
- 单集视频可以显示当前视频信息，但不显示无意义的剧集切换列表。

页面刷新时根据当前 `KEY_ROOM_ID` 恢复匹配的快照。房间号继续使用现有 `n-ellipsis` 单行省略显示。

## 错误处理与安全

- Android 播放结束事件采用每媒体项一次性门控，避免 Media3 重复回调触发多次下一集加载。
- 自动切集与手工切集沿用现有加载 generation 和取消机制，旧请求不得覆盖新状态。
- H5 快照属于不可信本地输入，渲染和发送前必须重新规范化。
- H5 不把快照中的字符串作为 HTML 注入，只通过 Vue 文本绑定渲染。
- Presence 续租失败仍按现有策略处理，不因日志去重而改变在线判定。

## 测试策略

### Android JVM 测试

- 日志时间字段、格式化、20 条缓冲和 5 行显示限制。
- 播放页连接状态和日志均受 `infoVisible` 控制。
- 二维码卡片无全屏遮罩、位于右上角且返回键关闭。
- 房间号短值原样、长值中间省略和极端长度边界。
- `STATE_ENDED` 每个媒体项只产生一次事件，加载新媒体后可再次产生。
- 有下一集时自动加载、最后一集不循环、详情延迟返回后自动加载。
- 手工新加载清除旧的待自动切集，解析失败不连续重试。
- Presence 续租不重复记录关联日志，断开后重连可重新记录。

### H5 Node 测试

- 快照规范化、版本校验、损坏 JSON 和房间不匹配降级。
- ACK 成功后保存并跳转；失败时既不保存也不跳转。
- 四个投射入口提供当前视频和剧集元数据。
- 控制页刷新恢复快照、当前剧集高亮和单集降级。
- 剧集切换 ACK 成功后更新，失败后保留旧状态。
- Presence 仍按 5 秒续租，投射控制流程不额外调用刷新。

### 构建验证

- Android：debug/release JVM 测试、debug/release lint、debug/release APK 构建、AndroidTest Kotlin 编译。
- H5：全部 `node --test tests/*.test.mjs` 和 `npm run build`。
- 执行 UTF-8 无 BOM、`git diff --check` 和工作树范围检查。

### 真机验收边界

自动化构建不能替代 Android TV 真机验收。仍需在目标电视验证：

- 遥控器触发控制层后，日志、连接状态和底部信息同步出现与隐藏。
- 左下角 5 行日志不遮挡视频控制区域和 TV 安全区。
- 右上角二维码可扫码且不遮挡连接状态。
- 真实 HLS/MP4 播放结束后只自动进入一次下一集。
- H5 刷新后剧集列表恢复并可继续切换。
